## 1. 排障标准流程（六步）

### ① 症状分层（先定层，别一上来就查代码）
读《已排除方向》§1。分清：设备侧失声 / 换歌间隙静默 / 服务端没推流 / 网络差——四层四查法。
**同歌失声 vs 换歌静默必须先分开**（切歌 ~2.25s 对齐垫片是设计，不是 bug）。

### ② 挂常态监控（必须先于任何操作）
按《监控台手册》§1 三步启动（上传 → 停旧 → 启动+自检）。自检 10 条 PASS 是硬门槛。
起隔离/测试实例前**必须补 iptables 护栏**（先 `avahi-browse` 确认设备真实 IP，HiVi 是 .30 但会变；测完立即删）。

### ③ 读判定（监控台自动下结论）
- `verdict.log` / `latest.txt` 看判定码；《监控台手册》§5 四个剧本照着读：
  **A 健康 / B 设备僵死 / B' 接管期（别误判成 B）/ C 服务端没推流 / D 网络真差**。
- `全量汇总` 命令看链路对比 + WiFi + 抓包 + 资源 + 判定分布。

### ④ 监控判定不了 → 深度取证（抓包）
按《取证方法论》§2 挂工具：探针三件套（e3 重传请求是 **P0**，e2 ICMP 是伪证只作参考）+ 环形 pcap
（`-i eno1-ovs -s 96 -C 10 -W 24`，双向 `host` 过滤）。

### ⑤ 两级对账定性（决定性环节）
按《取证方法论》§2.4：
- **分钟级粗筛**：每分钟 RTP seq 区间 vs 请求 seq 区间、命中率 → 排除/确认"大范围错位"类假说；
- **秒级定性**：burst 分组（间隔>2s）→ 算 `delta0 = min(req)−sent@start`、`delta1 = max(req)−sent@end`、
  `future% = req>sent@end 占比`。**future% ≈ 全部 ⇒ 设备在要还没产生的包 ⇒ 查服务端供料，不是查网络**。
- 同时看桥 tick 指纹：《取证方法论》§4 速查表（`late` ~22/s=投递侧钳1x、`queueMs` 恒 0~8ms=jitter buffer 缺失、
  `silenceChunks=0` 不代表没欠料）。

### ⑥ 结论回填
- 修复归属哪个 commit、推翻了什么结论 → 回填《已排除方向》§2.4；
- 根因定性 → 权威方案文档（改延迟/桥代码必须同步三份权威文档）；
- 新假说被推翻的过程 → 补《取证方法论》§1 误判时间线。


**中途三次误判全部靠流程纠偏**（详见《取证方法论》§1）：修复无效回头重查（2048 救不了）、

## 3. 排障纪律（铁律速查，细节见源文档）

1. **修复后真机无效 = 假说错误的最硬证据**，立刻回头，不要给错误假说加补丁。
2. **对账必须同一时间窗**；跨窗比对会制造"seq 错位"类假象。
3. **时间口径**：`docker logs -t`=UTC，`tcpdump`/`date`=CST(UTC+8)，混用会得出相反结论。
4. **伪证清单**（取证文档 §3，九条）：ICMP 恒零、pcap 只证"服务端发了"、"没看到≠不存在"、
   pcap 文件边界盲区、观测代码自身 bug（新指标首次真实事件必须验证"会动"）……
5. **恒定的异常数字是行为的指纹，不是随机噪声**：657 条恒定、future 656/657 恒定 → 设备固定行为（追赶）。
6. **跨口径/挑样本对比一律作废**：口径、样本、条件三者列出才能下结论。
7. **改延迟/桥/投递代码必须同步三份权威文档**；静态守卫按字面量钉行，补日志只能新增独立语句。
