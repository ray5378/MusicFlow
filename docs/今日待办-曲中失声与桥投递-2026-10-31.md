## 1. 当天结论（一句话）

**曲中「约 2 秒失声后自愈」的直接原因是「设备保持深度 < 空口连续丢包时长」**：
设备保持深度由 SYNC 包广播的 `rtp_timestamp_latency`（= 锚点公式的 `L`）决定，缺省只有
**1.0s**，而 240 现场实测空口一次连续丢包 **≈240 包 ≈ 1.92s** ⇒ 设备必被抽干。
重传缓冲（2048 包 ≈16.4s）只保证「补得到」，不保证「补得及」。

## 2. 根因认识的三次演进（每条都被真机证伪过）

| 轮次 | 假设 | 真机结果 | 教训 |
|------|------|---------|------|
| ① ad294ae2 原版 | 桥换代后一次性 bulk 灌 6s 即可 | `bulk durUs=1725000`（判据说 6s）→ `rebase +2765314µs` → 秒级卡顿 | 判据口径错：`tail−lo` 是时间线口径，深锚 4s + 垫片 2.5s 把内容起点顶到 lo 之上 4.5s |
| ② Fix A（整代常数垫片） | 垫片把内容推出窗口 | 曲末续静音被打断，RTP 掉回 1pps | 「注释写整代 +Δ」被当成契约，历史代码其实是衰减的 |
| ③ Fix D（窗口上界跟随水位） | 窗口 `(watermark, hi]` 上界不随水位，与 bulk 形成永久死锁 | 秒级卡顿消失 | 反向：`tailVsHiUs` 恒 7.86s 是**常态**（泵预填充 10.6s），不是故障指纹 |
| ④ **保持深度（本日定论）** | 设备侧 hold 1.0s < 空口空洞 1.92s | 抬到 2.5s 后，同形态爆发仍在但**不再失声** | 「扛住 ≠ 消除」，见 §5 |

## 5. 未闭环（按优先级）

### P0：已改但没闭环

- **P0-1 `miss == future` 的物理含义未解释清楚**：设备索要的都是「我们尚未发出」的 seq。
  这与「丢包重传」的直觉冲突，目前只有现象、没有机制解释。**必须靠双向 pcap 定论**。
- **P0-2 切歌 / 跨曲路径**：bulk 只在换代触发，尚未系统验证。
- **P0-3 多成员 / 纯 AirPlay 组**：`deltaUs / deltaP95Us / queueMs` 三成员相等只在单测里，真机未验。

### P1：结构上没根治

- **P1-1 领先量没有「设定点」**：Fix D 只让窗口跟随水位，没回答「领先量应该是多少」。
  真机落点 1.25s 是 bulk 残留烧完的巧合，路径依赖。→ D1：窗口 `lo/hi` 与 `anchorUs` 两侧
  同时感知垫片，判据「同一墙钟时刻，内容前沿 − 播放头 = 常数，且不随代次增长」。
- **P1-2 跨进程 cache 陈旧洞剩两个**：`sendspinDelayUsOfClient` / `bridgeAnchorShiftUsOf`
  仍读 cache（`mixedAnchorLeadUsOf` 已绕）。凡「前端可改且子进程实时读」的值必须绕 cache 直查。

### P2：遥测与注释的坑（已踩）

- **P2-1 `queueMs` 一名三义**：`bridge-window queueMs`（BridgeSource 待入会话字节，实测恒 0）、
  `tick queueMs`（RAOP Tx 队列，~200）、`tick inQueueMs`（会话 ingest 队列，~1250–2775）。
- **P2-2 `BRIDGE_BACKFILL_MAX_US` 注释已失效**：仍写「常态窗口宽仅 1s，纯防御异常大帧」，
  实际它是 bulk 上限 + Fix D 的领先硬上限。应补「= 8s hardCap − 2s 余量，改它必须同步核算」。
- **P2-3 `tailVsHiUs` 天生 >0**：泵预填充 10.6s 决定，稳态 7.86s 是常态，日志里缺基线说明。

### P3：数据面问题（当天实际踩到）

- **P3-1 当天没有抓包**：`/tmp/pcap` 为空，唯一的 tcpdump 是 Oct30 留下只抓 TCP 的旧探针。
  设备端真相无独立证据。已补环形抓包 `/tmp/mfpc/`（`udp and host <HiVi-IP>`，4.8h 覆盖）。
  ⚠️ 坑：写 `/tmp/pcap` 直接失败——tcpdump 启动后降权为 `tcpdump` 用户，而目录 root 755 不可写，
  必须落到 777 目录。
- **P3-2 哨兵日志无时间戳**：`docker logs` 未带 `-t`，须另起带时间戳的查询对齐。
- **P3-3 `seq0=` 不可信**：打印发生在窗口重置**之前**，打出来的是上一个聚合窗口的首包。
  判范围只能用 `seq1` + `cur`。
- **P3-4 `[raop-loss]` 缺 `resent=`**：只报「没补上的条数」，不报成功补发数，
  「补发到底成没成」仍不可观测（这是 11:32 那次误判的根源）。
- **P3-5 旧探针未清理**：`/tmp/mf410_udp.py` 仍每分钟起一次 15s tcpdump。
